# MAN VS MACHINE

An original 2D arcade fighting game built in **Godot 4.6** (GDScript, GL Compatibility renderer).
One human boxer, **Marcus "Iron" Cole**, fights his way up a ladder of five combat robots, ending with the final boss, **OVERLORD**.

Everything here is original: the art, animation, stages, music, sound effects, font and logo were all generated by the scripts in `tools/`. No third-party assets are used.

---

## Launching

1. Open Godot 4.6 and **Import** `project.godot` from this folder, then press **F5**.
   Or, from a terminal:

   ```bash
   Godot.exe --path "C:/Users/Matthew/Desktop/12DT1/Man-Vs-Machine1/man-vs-machine-1"
   ```
2. The game opens at 1280×720. It renders internally at 640×360 and scales by whole numbers, so the pixel art stays sharp. Fullscreen is in **Settings**.

## Modes

| Mode | Description |
|---|---|
| **Arcade** | Fight SPARK → BULWARK → VOLT → RAZOR → OVERLORD. Each fight starts with a VS screen showing your ladder progress. The CPU gets harder as you climb. If you lose, choose **Retry** or **Restart Arcade**. Beating OVERLORD shows the ending, your score and the saved high score. |
| **Versus (2P)** | Player 2 picks a robot and controls it from the same keyboard (or a second gamepad). |
| **Training** | Pick any robot as a dummy. Health and meter refill automatically. **Backspace** cycles the dummy's behaviour (stand / crouch / guard high / guard low / jump). **F1** shows hitboxes. The HUD shows combo damage. |
| Demo | After 25 seconds idle on the title screen, a CPU-vs-CPU attract demo plays. Press any key to return. |

## Controls

| Action | Player 1 | Player 2 | Gamepad |
|---|---|---|---|
| Move | A / D | ← / → | D-pad / left stick |
| Jump | W | ↑ | |
| Crouch | S | ↓ | |
| Light punch | J | Num4 or `,` | X / Square |
| Heavy punch | K | Num5 or `.` | Y / Triangle |
| Light kick | U | Num1 or `M` | A / Cross |
| Heavy kick | I | Num2 or `/` | B / Circle |
| Block | L, or hold **back** | Num6 or `N`, or hold back | RB |
| Pause | Esc / P | | Start |
| Toggle hitboxes | F1 | | |

All of these are Godot Input Map actions (`p1_*`, `p2_*`, `pause`…), so they can be remapped under **Project Settings → Input Map**.

**Blocking:** hold away from the opponent (or hold L). Stand to block jump-ins (overheads). Crouch to block lows such as sweeps and the ground shockwaves.

### Iron Cole's special moves (written for facing right)

| Move | Command |
|---|---|
| **Iron Rush**: an advancing straight that knocks down | → → + Heavy Punch |
| **Rising Hook**: an uppercut that is invulnerable on startup, used as an anti-air | ↓ → + Heavy Punch |
| **Knockout Storm** (super, needs POWER MAX) | ↓ ↓ + Heavy Punch |

**Chains:** LP → LP → HP, LK → HK, and any light → special. Specials and the super can also cancel out of heavies that connect. Hits during a combo are damage-scaled. Jump-in attacks link into grounded follow-ups.

## The robots

| Robot | Stage | Style | Signature moves |
|---|---|---|---|
| **SPARK** | Industrial Arena | Balanced, predictable tutorial opponent | Spark Dash, Ion Pellet (slow projectile) |
| **BULWARK** | Industrial Arena | Slow tank, 1300 HP, armoured heavies, huge knockback; punishable recovery | Siege Hammer (armoured overhead), Quake Stomp (low shockwave) |
| **VOLT** | Neon Foundry | Very fast pressure, short recovery, 800 HP | Arc Bolt (fast projectile), Thunder Rush (3-hit electric dash) |
| **RAZOR** | Neon Foundry | Long blade reach, punishes whiffs | Blade Parry (counter stance), Edge Lunge |
| **OVERLORD** | Machine Core | Final boss: hovers, 1400 HP, gets more aggressive below 50% health | Annihilator Beam (crouch under it), Gravity Slam (shockwave), Orbital Strike (move away from the marker), Extinction Protocol (3 strikes), Phase Shift (teleport) |

All boss attacks are telegraphed: a charging ring, a blinking warning line, or a flashing target marker with an alarm.

## Project structure

```
project.godot            generated by tools/gen_project.py (display, input map, autoloads)
scenes/
  menus/                 main_menu, character_select, vs_screen, ending
  fighting/fight.tscn    the match (stage, fighters, effects, camera, HUD, pause, results)
  characters/fighter.tscn  one reusable fighter scene for every character
  stages/                industrial_arena, neon_foundry, machine_core
scripts/
  autoload/              Settings (persisted config/high score), Audio (SFX pool + music), Game (flow, ladder, font/theme)
  combat/                AttackData, CharacterData, InputFrame, InputBuffer (motions), Projectile, EffectsLayer
  characters/fighter.gd  shared fighter state machine (movement, attacks, blocking, reactions, animation)
  ai/                    PlayerController, AIController (state machine + per-robot profile), DummyController
  game/                  match.gd (round flow + hit resolution), stage.gd, debug_overlay.gd
  ui/                    hud, pause menu, results, menus, PixelText helper
data/characters/*.json   stats, frame data, specials and AI profiles (generated by tools/gen_data.py)
assets/
  characters/<id>/       <id>_sheet.png, <id>_anims.json (frame layout + derived hitboxes), <id>_portrait.png
  backgrounds/<stage>/   far / crowd / mid / floor parallax layers
  audio/sfx, audio/music synthesized WAVs
  fonts/pixel_font.png   6x9 bitmap font (built into a FontFile at runtime)
  ui/                    logo, icon
tools/                   Python asset generators (ignored by Godot via .gdignore)
tests/                   headless test scenes
```

### How combat works
- The match advances both fighters manually once per 60 Hz frame, in a fixed order: read inputs, apply facing, tick fighters, push fighters apart, tick projectiles, resolve hits. Player and AI both produce the same `InputFrame`, so they follow identical rules.
- Each attack (`AttackData`) defines startup, active and recovery frames, damage, chip, hitstun, blockstun, knockback, hit level (high/mid/low/overhead), knockdown, cancel list, multi-hit, armour, invulnerability, movement, projectile and telegraph.
- Hitboxes are taken from the art. When the sprite sheets are generated, the position of the striking glove, foot or blade on each active frame becomes the hitbox. Animation frames are mapped onto the startup/active/recovery phases, so the strike you see always matches the live hitbox. Extended limbs also act as hurtboxes, so long pokes can punish a whiff.
- There is one hit per active window unless a move is multi-hit, plus hit-stop, screen shake, sparks, block flashes, corner push-back, damage scaling, an input buffer that freezes during hit-stop, and a 6-frame press buffer.
- **Sprite sheet layout:** each animation is one row and frames run left to right in fixed-size cells. The origin (ground point between the feet) and the per-row `fps` / `loop` / `active_frames` values are in `<id>_anims.json`.

## Regenerating assets (optional)
You need Python 3. No extra packages are required.
```bash
cd tools
python chargen.py char_boxer robots   # character sheets, metadata, portraits (~1-2 min)
python gen_stages.py                  # stage layers
python gen_ui.py                      # font, logo, icon
python gen_audio.py                   # sfx + music (~1 min)
python gen_data.py                    # character JSON (frame data / AI)
python gen_project.py                 # project.godot + audio bus layout
```

## Known limitations
- The characters are skeletal pixel-art renders, not hand-drawn frame by frame. Animations have 2–7 key poses each, so they are stiffer than a commercial fighter.
- There are no throws. Iron Cole is the only playable character in Arcade mode; robots are playable only in Versus.
- Controls can only be remapped through Godot's Input Map; there is no in-game remap screen.
- AI balance has been tuned through automated CPU-vs-CPU runs and reasoning about the numbers, not extensive human play-testing. Difficulty can be changed in Settings.
- Audio is chiptune-style synthesis, and there is no announcer voice; on-screen text and stingers are used instead.
